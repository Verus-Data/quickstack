# Agent development harness

AGENTS.md is the project map. Path-scoped rules explain local conventions; skills hold checked reference material. Hooks give immediate feedback, lint enforces syntax and boundaries, tests prove behavior, and the project check command is the final local gate. CI runs those same project commands.

The shared TypeScript hooks use node APIs and run under Bun. `_lib.ts` handles payloads, process timeouts, project paths, and protocol output; `_shell.ts` parses shell commands so quoted examples and comments are not mistaken for execution. Generated-output guards protect tool-owned files; stack and application guards own their additional boundaries. Typecheck-on-write optionally runs the project's `before-typecheck.ts` helper before checking TypeScript. Missing tools and advisory timeouts remain quiet.

`/test` scopes feedback before the full test command. `/check` runs the complete gate. `/feature` records a design, reviews it, implements and verifies in an isolated worktree, and hands off a reviewed PR. The architect and reviewer are read-only. Use documented development commands, inspect on-disk logs, and terminate only processes you started. Keep secrets out of commands and logs.

To inspect the harness, read `.claude/settings.json`, confirm each wired file exists once, then run the shipped hook tests through the project test command. Test guards with a deny and a near miss; test advisory hooks with a realistic temporary project. Never treat a hook as a replacement for tests or review.

The repo is a bun workspace. The harness belongs to the root: `.claude/`, lefthook, CI, the root Biome config, and the hook tests under `tests/hooks/` (`bun run test:hooks`). Each package under `apps/` or `packages/` owns its source, tests, tsconfig and any Biome plugins in a nested `biome.json` that extends the root. Hooks resolve per package where it matters: typecheck-on-write checks the nearest `tsconfig.json`, guard-generated covers each package's `dist/` and `coverage/`, guard-boundaries applies to the nearest package's `src/`, and project-status reads each app's `logs/cli.jsonl`. The CLI-specific rules live in `.claude/rules/cli/` and are scoped to `apps/cli/`; a new app adds its own rules directory and, if it needs different source boundaries, narrows guard-boundaries.

When extending the project, put a rule at the narrowest relevant path, add the behavior test first, and document new commands and debugging information in AGENTS.md. After changing hooks, rerun the hook suite and exercise one payload manually. Clean completed disposable worktrees after preserving unique source and deliverables.
