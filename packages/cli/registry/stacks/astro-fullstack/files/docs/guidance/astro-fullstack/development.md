# Astro site + Effect API development

`dev:api` and `dev:web` run `bun run --cwd` into their workspace; `dev:bg` and `dev:stop` invoke `scripts/dev-bg.ts start` and `stop`. `dev:api` runs `apps/api/src/platform/node.ts` on Node with watch mode on `PORT_API` and `--env-file-if-exists` pointing at the root `.env`. `dev:web` passes `--ignore-lock`, because Astro backgrounds itself when it detects an agent; `astro.config.mjs` sets `server.port` from `PORT_WEB`, falling back to 4321. `build` bundles the API with Bun targeting Node, without inlining env, then runs `astro build`; `start` runs the bundle with the same env-file flag. The shipped wrapper owns checkout servers and capped logs (`dev.log`, `dev.jsonl`, `server.jsonl`), preserving the previous run. Wire `logs` to `scripts/logs.ts` and `dev:status` to `scripts/dev-bg.ts status`. Agents use `dev:bg`, `dev:stop`, `dev:status` and `logs --help`.

The API and Vitest run on Node. Never `bun test` and never `--bun`. Bun doesn't pass its loaded `.env` to a Node child. `@astrojs/check` can lag the newest TypeScript major: if it rejects the installed TypeScript, install the previous major and record it under Build workarounds. If content types or route types look stale, delete `apps/web/.astro/`.
